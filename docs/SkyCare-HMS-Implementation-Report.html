1. Executive Summary

SkyCare is a multi-tenant Hospital Management System (HMS) delivered as a SaaS platform. Every subscribing hospital gets a branded staff dashboard, a patient portal, and a public hospital website — all from one codebase.

Key Facts:
  • Product: SkyCare — The Smart Hospital OS for Africa
  • Developer: Skyhouse Technologies
  • Version: 0.1.0 (Initial Release)
  • Completion: ~82%
  • Git Repo: github.com/liamsedun/skycare
  • Production Domain: skycare.app
  • Supabase Ref: pvakwxeusbxesdealuuc

What's Built

  • 20 fully functional modules (Patients, Appointments, Pharmacy, Lab, Wards, Billing, Banking, HR, Payroll, etc.)
  • Complete multi-tenancy with PostgreSQL RLS isolation
  • 25 staff roles with per-user module access grants
  • Patient portal with self-booking, bill payment, family management
  • Auto-provisioned public hospital website with CMS
  • AI-powered pharmacy (7 features: forecasting, recommendations, interactions, alternatives, pricing, anomalies, auto-reorder)
  • Nigerian payroll engine (PAYE, NHIS, NHF, Pension)
  • Online payments via Paystack
  • Dark mode ("Dusk & Gold" theme)
  • Mobile-first PWA with bottom navigation
  • Full audit trail and security hardening

What's Not Built

  • SMS integration
  • Email notifications (external)
  • Full insurance claims UI
  • Telemedicine (video consultations)
  • Advanced analytics dashboards
  • E2E test suite
  • API documentation (OpenAPI/Swagger)
  • Redis caching (currently in-memory)
  • WebSocket chat (currently 5s polling)

Key Architectural Decisions

  1. Multi-tenant via RLS — Every table has tenant_id. Service-client queries MUST filter it.
  2. JWT claims are source of truth — app_metadata { role, tenant_id, branch_id }. Never trust client-supplied tenant/org IDs.
  3. Service client bypasses RLS — Must always add tenant_id filter manually.
  4. withAuth/withStaff wraps every API route — Gives ctx { user, claims, tenantId, branchId, role, supabase, svc }.
  5. Audit duality — DB triggers log RLS-scoped writes; API layer logs service-client writes. Never double-log.
  6. No cookies() inside unstable_cache — Use createServiceClient() instead.

5. Multi-Tenancy Model

Isolation Contract

  • Tenant = hospital. tenants row with unique slug → {slug}.skycare.app
  • JWT claims carry { tenant_id, role, branch_id } — set at login
  • RLS helper functions read claims — no per-request DB lookups
  • Branch layer (Enterprise): staff scoped to branch_id

Three-Layer Isolation

  1. PostgreSQL RLS — row-level, not bypassable via client keys
  2. API-layer withAuth/withStaff — requireTenant(ctx) throws for non-tenant callers
  3. Service-client queries MUST filter tenant_id = requireTenant(ctx) — service role bypasses RLS

RLS Helper Functions

Module Access System

  • Per-user users.module_access JSONB grants
  • Three levels: full, view_only, none
  • navForRole() uses grants as authoritative (overrides role defaults when set)
  • requireModuleLevel() guards API routes per module

Security Controls

  • Rate limiting: 100 req/min (standard), 10 req/min (auth)
  • Login lockout: 5 failed attempts → 15 min lockout
  • Idle auto-logout: 15 minutes
  • CSP headers, X-Frame-Options DENY, nosniff
  • RLS on 100+ tables
  • Function EXECUTE hardening (migrations 0097/0100)
  • Cross-tenant isolation verified by smoke tests

10. Security Implementation

Defense-in-Depth

Internet → Cloudflare (WAF+DDoS+Bot) → Netlify (CDN) → Next.js Proxy (Abuse+Auth) → API (Rate Limit+RLS) → Supabase (DB Isolation)

Security Headers

  • CSP: script-src 'self' 'unsafe-inline' 'unsafe-eval'; frame-src 'self' https://www.google.com https://maps.google.com
  • X-Frame-Options: DENY
  • X-Content-Type-Options: nosniff
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: camera/microphone/geolocation/payment disabled

Rate Limiting

Endpoint TypeLimit
Standard API100 req/min/IP

Identifier resolution20 req/min/IP
File uploads10 req/min/IP
Payment20 req/min/IP

  • 7 role-only policies rewritten to also require tenant_id

  • SECURITY DEFINER RPCs locked: REVOKE ALL FROM PUBLIC, anon, authenticated + grant service_role

14. Caching & Performance

Cache Strategy

  • unstable_cache with createServiceClient() (no cookies() in cache)
  • revalidateTag() for targeted invalidation on writes
  • Stampede protection with 30s cooldown
  • Cache invalidation in 12+ write endpoints

Cache-Control Headers

  • _next/static/*: 1 year (immutable)
  • /images/*: 30 days
  • /icons/*: 30 days

Performance Optimizations

  • Composite indexes on (tenant_id, ...) for every hot query path
  • analytics_daily upserted by triggers; dashboards read aggregates
  • Pagination everywhere (cursor-based for large tables)
  • PWA + CDN for static assets
  • Turbopack for fast builds
